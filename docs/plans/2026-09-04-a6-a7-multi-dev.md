# Constitution A6 + A7 Implementation Plan (Multi-Dev Aspirational Features)

> **For Hermes:** Execute task-by-task. Each task is bite-sized; commit after each.

**Goal:** Close the last two open items in the ToolRecall constitution Appendix A — A7 (CI benchmark regression gate) and A6 (shared network daemon) — completing the multi-agent/multi-dev story.

**Architecture:** A7 first (low risk, no protocol change): a self-contained benchmark gate that runs the existing `--dry-run` harness against deterministic fixtures and fails on cache-hit-rate regression. A6 second (bigger): extend the UDS daemon with an authenticated TCP listener so a team shares one warm cache. A6 reuses the just-landed A4 per-agent policy work for per-remote-agent authorization.

**Tech stack:** stdlib only (`socket`, `hashlib`, `hmac`, `secrets`, `tomllib`). Zero deps is NON-NEGOTIABLE (Constitution I). No TLS library — wire auth via HMAC-SHA256 challenge-response; transport security = loopback/VPN/SSH-tunnel (documented trust model, matches SECURITY.md).

**Order rationale:** A7 before A6 — A6 changes cache-hit characteristics (shared cache = higher hit rates), so the regression gate must exist before the feature that shifts baselines.

## Track 1 — A7: CI Benchmark Regression Gate

**Problem:** `make bench-*` targets exist but no CI gate fails when cache logic regresses. Constitution X requires: "Every commit that touches cache logic, the proxy, or the daemon must pass the two-arm benchmark without regression."

**Design decisions (made):**
- CI runs the **dry-run** harness (`bench/run_arm.py --dry-run`) — no API keys in CI, deterministic, fast (seconds). Live-cost benchmarks stay manual (Constitution IX: billed dollars, never estimates).
- Metric that must not regress: **terminal + file cache hit rate** on a fixed workload/seed, read from the run DB. Threshold: `>= previous recorded baseline` (stored in a committed JSON, updated only with justification in the PR).
- Gated paths (trigger the job): `toolrecall/cache.py`, `toolrecall/daemon.py`, `toolrecall/proxy.py`, `toolrecall/_db.py`, `toolrecall/transport.py`.

### Task 1.1: Deterministic benchmark fixture manifest
**Files:** Create `bench/fixtures/manifest.json`; Create `bench/gate_fixtures.py`
- Generate a fixed set of ~30 fixture files (varying sizes 1KB–200KB) with `--seed 42` determinism; manifest records `(path, size, sha256)`.
- Test: `tests/test_bench_gate.py::test_manifest_deterministic` — generate twice into temp dirs, compare manifests equal.

### Task 1.2: Gate runner — two arms, dry mode
**Files:** Create `bench/gate.py`
- Runs arm=naive and arm=toolrecall against the fixture manifest via `bench/run_arm.py --dry-run` (subprocess, isolated `TOOLRECALL_CACHE_DB` + `TOOLRECALL_TRANSPORT` per arm — the e2e pattern from `/tmp/e2e_durability.py`).
- Emits JSON: `{arm, hits, misses, hit_rate, entries, wall_s}` per arm to stdout and `bench/gate-last.json`.
- Test: `test_gate_runs_both_arms` — both arms present, hit_rate in [0,1], toolrecall arm hit_rate > naive arm (0 hits by construction).

### Task 1.3: Baseline storage + comparison logic
**Files:** Create `bench/baseline.json` (committed); Create `bench/gate.py:compare()`
- `compare(current, baseline)` returns list of regressions: hit_rate drop > 2 percentage points on either arm, or wall_s 3× slower (CI noise guard).
- Test: `test_compare_flags_regression`, `test_compare_allows_noise` (1pp drop passes), `test_compare_new_entry_passes`.

### Task 1.4: Make target + CI workflow
**Files:** Modify `Makefile` (add `bench-gate` target after `bench-dry`); Create `.github/workflows/bench-gate.yml`
- `bench-gate: python3 bench/gate.py --baseline bench/baseline.json` → exit 1 on regression.
- Workflow: `on: pull_request` + `paths:` filter on the gated files above; steps: checkout → setup-python 3.11 → `uv pip install -e ".[dev]"` → `python3 bench/gate.py --baseline bench/baseline.json --json > gate.json` → upload artifact.
- Manual refresh path: `make bench-gate-update` (regenerates baseline; PR description must justify the delta — Constitution IX evidence-first).

### Task 1.5: Docs + constitution row
**Files:** Modify `docs/BENCHMARK.md` (gate section); Modify `../workspace/constitution-toolrecall.md` Appendix A row A7 → ✅ FIXED.
- Commit: `feat(bench): CI regression gate (A7)`.

## Track 2 — A6: Shared Network Daemon (team cache)

**Problem:** Daemon is localhost-UDS only (Constitution X target): "network-accessible shared daemon (auth, TLS) so a whole team warms one cache."

**Design decisions (made — flag any you disagree with before Track 2 starts):**

| Decision | Choice | Rationale / alternative rejected |
|---|---|---|
| Transport | TCP listener alongside UDS, opt-in | UDS stays default/local; TCP only when `[network]` configured. TLS lib would break zero-deps. |
| Auth | HMAC-SHA256 challenge-response per connection, pre-shared token | No plaintext token on the wire; no deps (`hmac` stdlib). mTLS rejected (needs certs + deps). |
| Token storage | `[network] token` in config or `TOOLRECALL_NETWORK_TOKEN` env; `chmod 600` guidance | Same pattern as existing `TOOLRECALL_EDGE_TOKEN`. |
| Transport security | Documented: run on loopback/VPN/SSH tunnel; threat model in SECURITY.md §new | TLS-in-stdlib (`ssl` module) is possible later as opt-in; start without. |
| Per-agent authz | Reuse A4: `[network.clients."<agent>"]` maps token-id → `[mcp.clients]` policy entry | A4 machinery (effective_policy) already exists. |
| Multi-writer safety | Single daemon process owns SQLite (unchanged); remote clients are just IPC clients over TCP | Rejects multi-writer SQLite (libsql sync exists for that as opt-in extra). |

### Task 2.1: Config schema + env parity
**Files:** Modify `toolrecall/config.py` (network properties + ENV_MAP), `toolrecall/config.toml` (documented `[network]` section), `docs/CONFIG_REFERENCE.md`
- `[network] enabled=false, bind="127.0.0.1", port=8570, token=""`; env: `TOOLRECALL_NETWORK_ENABLED/_BIND/_PORT/_TOKEN`.
- Add `network` + `network.clients` to the A3 known-sections set.
- Test: `test_network_config_defaults` (enabled=False, bind loopback).

### Task 2.2: HMAC challenge-response protocol (TDD)
**Files:** Create `toolrecall/network_auth.py`; Test `tests/test_network_auth.py`
- Server sends 32-byte nonce; client replies `hmac_sha256(token, nonce)`; constant-time compare (`hmac.compare_digest`); 3-second auth window then disconnect.
- ~80 LOC, pure stdlib. Tests: `test_roundtrip_ok`, `test_wrong_token_rejected`, `test_nonce_never_repeats` (server keeps last N nonces), `test_replay_rejected`, `test_timeout`.

### Task 2.3: TCP listener in DaemonServer
**Files:** Modify `toolrecall/daemon.py` (`start()` spawns `_run_tcp_listener` thread when `[network].enabled`; `_handle_tcp(conn)` = auth handshake → same `_route()` as UDS)
- Per-connection: nonce → verify → loop `receive_message/send_message` (transport.py framing already transport-agnostic — TCP fallback for Windows proves it).
- **Clamp** `TOOLRECALL_MAX_MSG` behavior identical to UDS; per-connection `client` identity = authenticated token-id, NOT client-supplied (server overrides `request["client"]` after auth — prevents policy spoofing of the A4 field).
- Tests: `test_tcp_ping_roundtrip`, `test_unauthenticated_ping_rejected`, `test_client_override_cannot_spoof`.

### Task 2.4: Client transport + auto-detect
**Files:** Modify `toolrecall/transport.py` (`TransportClient` accepts `tcp://host:port` — Windows path already does TCP; add token from config/env), `toolrecall/client.py` (fallback order: UDS → TCP → error, explicit only — never silently prefer remote)
- `TOOLRECALL_TRANSPORT=tcp://cachhost:8570` selects remote; local UDS remains default when unset.
- Test: `test_client_uses_tcp_when_configured` (against Task 2.3's listener on an ephemeral port).

### Task 2.5: Security gate for remote conns
**Files:** Modify `toolrecall/daemon.py` `SecurityGate` usage on TCP path; Modify `SECURITY.md` (new §: network daemon threat model)
- Remote = untrusted-ish: default-deny paths apply per token-id via A4 policy; `allow_terminal` defaults false for ALL remote tokens unless explicitly enabled per client; sensitive-file blocklist unchanged; document: "compromised token = exactly the scoped policy, nothing more."
- Test: `test_remote_terminal_denied_by_default`, `test_remote_scoped_to_policy`.

### Task 2.6: Cache semantics across machines (the honest part)
**Files:** Modify `docs/ARCHITECTURE.md` §network; Modify `docs/COST_SAVINGS.md`
- State plainly: file-cache entries keyed by path remain valid cross-machine only when the team shares the filesystem (NFS/mount) or when the hit is content-addressed; API-proxy and terminal entries are host-agnostic and benefit fully. Terminal cwd-scoping (A1) means cross-machine terminal hits require matching cwd — expected, correct.
- No code — docs prevent the "why is my hit rate weird" support burden.

### Task 2.7: e2e + docs + constitution row
**Files:** Create `tests/test_e2e_network_daemon.py`; Modify `README.md` (team setup snippet), `docs/DOCKER.md` (docker-compose service for shared daemon); Modify constitution A6 row → ✅ FIXED.
- e2e: start daemon with `[network]` on ephemeral port, second "remote" client process connects with token, shares cache entries with the local client (write via local, read via remote = hit).
- Commit: `feat(network): shared team daemon with HMAC auth (A6)`.

1. **A7 baseline in repo?** Committed `bench/baseline.json` means CI stays hermetic but every intentional improvement needs a baseline-update PR. Alternative: store baseline as CI artifact (floats between runners, noisy). **Recommendation: committed file.**
